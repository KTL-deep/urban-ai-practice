# Школы и доступность · Павловск

Локальное интерактивное приложение практической работы №3. Оно **не загружает данные города** и читает результаты практики №2 только для чтения. При отсутствии данных приложение останавливается с перечнем недостающих файлов: карта и выводы по Павловску не подменяются демонстрационными результатами.

В текущем проекте реальные данные Павловска восстановлены в `pavlovsk_study_data/`; компактная проверенная копия обязательных файлов хранится в [`school-placement/input/`](input/README.md) для запуска после передачи репозитория без архива города. Рассчитанные варианты А, Б, В и полный рейтинг находятся в `school-placement/results/`. При открытии приложения готовые сценарии и рейтинг загружаются автоматически. Подробное сравнение и ограничения — в [REPORT.md](REPORT.md).

## Данные

Укажите каталог, созданный `examples/pavlovsk_study.ipynb` (путь в ноутбуке относительно каталога запуска, поэтому он может находиться вне `examples/`). Обязательны `blocks.geojson` **или** `blocks_indicators.geojson` (поля `block_id`, `population`, `capacity_school`, EPSG:4326) и `accessibility_matrix_drive.csv` (строки и столбцы — ID кварталов). Для проверки совпадения базы добавьте `provision_schools.csv`; полезны `study_info.json`, `boundary.geojson`. Приложение не восстанавливает отсутствующие времена в пути по прямой линии и не запускает загрузочные ячейки ноутбука. Если сохранился только локальный `graph_drive.pickle`, матрицу необходимо отдельно получить по коду расчёта из ноутбука на тех же сохранённых кварталах; не запускайте ноутбук целиком, поскольку в нём есть сетевые загрузки.

Проверяются ID, порядок строк/столбцов, геометрии, CRS, пропуски и неотрицательность числовых полей. Для исходной `capacity_school` строго повторяется явное правило ноутбука: отсутствующие оценки заменяются нулём, остальные округляются до целого; нечисловые значения отклоняются. Пропуски населения и времени — ошибка. Направленная матрица не симметризуется. При наличии сохранённого `provision_schools.csv` несоответствие исходному расчёту **блокирует** запуск; при его отсутствии показывается предупреждение об отсутствии независимой сверки.

### Восстановление результатов практики №2, если они не сохранились

```powershell
.venv\Scripts\python.exe -u school-placement\reproduce_study.py --stage all
```

Эта **отдельная** команда запускает исходные расчётные ячейки `examples/pavlovsk_study.ipynb` без изменения ноутбука. Для неё требуется дополнительно `matplotlib` (`.venv\Scripts\python.exe -m pip install "matplotlib>=3.9,<4"`). Запускайте из корня репозитория. Если файлов нет, она обращается к Nominatim за границей и скачивает официальный `saint_petersburg.zip` (~405 МБ) с GitHub; если файлы уже сохранены, используются локальные копии. Результаты записываются в `pavlovsk_study_data/`; исходный ноутбук помещает в этот каталог `.gitignore` с `*`, поэтому Git не включит большие данные автоматически. Для отдельной проверки границы: `--stage boundary`; для кварталов, матрицы и школ без остальных показателей: `--stage core`; для повторной сверки и вывода базовых CSV/JSON **без запуска ячеек и сети**: `--stage verify`. Обычный запуск приложения скачивания не выполняет.

## Запуск на Windows (PowerShell, без прав администратора)

Если совместимое окружение проекта уже есть:

```powershell
.venv\Scripts\Activate.ps1
python -m pip install "blocksnet==1.0.0a9" "dash>=2.18,<4" "dash-leaflet>=1.0,<2" "pytest>=7,<10"
python school-placement\app.py --data-dir "C:\ПУТЬ\К\pavlovsk_study_data"
```

Если окружения нет, используйте доступный совместимый Python (рекомендуется 3.11, также проверяется 3.12):

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install "blocksnet==1.0.0a9" "dash>=2.18,<4" "dash-leaflet>=1.0,<2" "pytest>=7,<10"
.venv\Scripts\python.exe school-placement\app.py --data-dir "C:\ПУТЬ\К\pavlovsk_study_data"
```

Откройте **http://127.0.0.1:8050/**. Без `--data-dir` используется `pavlovsk_study_data` в корне репозитория, а при отсутствии этого каталога — проверенная копия `school-placement/input/`. При повторном запуске данные берутся только с диска, без интернета. Для запуска всех тестов: `.venv\Scripts\python.exe -m pytest tests -q` (старым тестам HTML-дашборда дополнительно нужны зависимости `.[dashboard]`).

## Работа с приложением

Для полностью воспроизводимого учебного эксперимента ручные варианты и обоснования сначала фиксируются в `results/manual_choices.json`. Только после этого запускается `.venv\Scripts\python.exe -u school-placement\complete_experiment.py`: сначала он рассчитывает и сохраняет А/Б, затем проверяет все кварталы для В. При неполном переборе лучший по территории **не** объявляется. Результаты автоматически появятся в `results/`, а сценарии будут доступны в браузере при следующем запуске приложения с тем же каталогом данных.

1. На карте нажмите квартал или выберите его ID слева, задайте число мест и нажмите «Добавить школу». Значок × удаляет школу из черновика. Можно добавить несколько школ, включая несколько в одном квартале.
2. Для **А** задайте одну школу на 600 мест, для **Б** — две по 300 в разных кварталах. Введите обоснование выбора **до** автоматического поиска, затем рассчитайте и сохраните каждый сценарий. Результаты записываются отдельно в `school-placement/results/scenarios.json`, `scenario_comparison.csv`, `scenario_А.csv` и `scenario_Б.csv` (для В аналогично); сценарии восстанавливаются при повторном запуске с тем же каталогом данных. Сброс очищает черновик и просмотр, но не удаляет сохранённые сценарии. Новый расчёт с тем же названием заменяет прежний сценарий этого имени.
3. После сохранения А и Б нажмите «Разместить автоматически»: прогресс покажет число проверенных кварталов и ошибок; успешный рейтинг для 600 мест сохраняется в `results/automatic_ranking.csv`, неполный — отдельно в `automatic_ranking_incomplete.csv`, не заменяя прежний успешный поиск (для другой вместимости добавляется её число в имя). **В** создаётся только при полностью успешном переборе для **600 мест**. В рейтинге видны все кандидаты; нажмите строку, чтобы открыть её на карте. Если несколько ID равноценны, перечисляются все; В показывает первый в стабильном порядке ID.
4. Выбирайте состояние в выпадающем списке «Сравнение сценариев», а режим карты — над картой. Несохранённые изменения в черновике не меняют карту. Экспортируйте таблицы в UTF-8 с BOM и разделителем `;` для Excel; GeoJSON содержит показатели выбранного состояния. Экспорт выполняется в браузер, исходные файлы не перезаписываются.

**Метод:** `blocksnet.analysis.provision.competitive_provision` версии 1.0.0a9 с конфигурацией `school`: 120 мест на 1000 жителей, 15 минут поездки автомобилем; сначала удовлетворение собственного спроса, затем целочисленное распределение оставшегося спроса между доступными кварталами при ограниченной вместимости. Дефицит — сумма `demand - demand_within`; при нулевой потребности доля обеспеченности не определена. Алгоритм библиотеки оптимизирует взвешенные связи, а не прямо минимизирует дефицит. Население и вместимость — оценки практики №2, не сведения о фактических земельных участках. Новые школы на карте обозначают **квартал**, не адрес строительства.

Вводные результаты и итоговый отчёт: [REPORT.md](REPORT.md). Исходные данные практики №2 остаются вне каталога приложения и открываются только для чтения.
